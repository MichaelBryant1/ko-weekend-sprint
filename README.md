# KO Weekend Sprint 🇰🇷

A small, private Korean learning app — Hangul sound board, the top **300 words**
(each with 3 example sentences), native-Korean **audio** on every item, and an
**FSRS-6** spaced-repetition review that tracks each user separately.

**Live app:** https://bryantanalytics.com/ko-weekend-sprint/
(also reachable at https://michaelbryant1.github.io/ko-weekend-sprint/ — it redirects to the line above)

---

## ⚙️ One-time setup before friends can log in (≈2 minutes)

The app uses Supabase email sign-in. Two small dashboard settings make it work
on phones. Do these once in the **JP Atlas** Supabase project
(`ylceljdbapxeynyqphcr`):

### 1. Allow the app URL (required — makes the email link work)
Dashboard → **Authentication → URL Configuration**
- **Site URL:** `https://bryantanalytics.com/ko-weekend-sprint/`
- **Redirect URLs → Add:**
  - `https://bryantanalytics.com/ko-weekend-sprint/**`
  - `https://michaelbryant1.github.io/ko-weekend-sprint/**`

With this set, a friend enters their email, taps the **link** in the email on
their phone, and the app opens already signed in.

### 2. (Optional) Enable the 6-digit code fallback
Dashboard → **Authentication → Email Templates → Magic Link** — add the code
to the template body so people can also type it in:
```html
<p>Your code: <b>{{ .Token }}</b></p>
<p>Or tap: <a href="{{ .ConfirmationURL }}">Sign in</a></p>
```

### 3. Add the people who are allowed in
Only emails on the allowlist can use the app. Add friends (run in the Supabase
SQL editor, or ask Claude):
```sql
insert into public.ko_sprint_allowed_users (email, display_name, role) values
  ('friend1@example.com', 'Friend One', 'student'),
  ('friend2@example.com', 'Friend Two', 'student')
on conflict (email) do nothing;
```

## What's inside

| Page | What it does |
|------|--------------|
| **Home** | Weekend-sprint goals (Hangul / Words mastered), due count, quick start |
| **Hangul** | 40 letters in 4 groups + a batchim (final-consonant) overview. Tap a tile → hear the letter name, see 3 example words, mark known. |
| **Write** | Stroke-order animations, touch/mouse tracing canvas, writing review cards, syllable-block examples, and a blank practice pad. |
| **Words** | All 300 words, searchable. Tap → word audio + 3 sentences (with audio) + romanization + English. |
| **Review** | FSRS-6 spaced repetition. Six directions, **scheduled independently**: letter→sound, sound→letter, symbol→write, write→symbol, word→meaning, **listen→meaning**. Rate Again / Hard / Good / Easy. |
| **Progress** | Streak, accuracy, mastered counts, reviews over the last 30 days. |

## Architecture

- **Frontend:** one static page (vanilla JS, no build step) — `docs/` on GitHub Pages.
- **Auth + data:** Supabase Auth (email) + Postgres with Row-Level Security.
  Every user only ever sees their own cards/logs; content is gated by an
  invite **allowlist**.
- **Audio:** 1,364 MP3s generated by ElevenLabs (native Korean voices —
  **Yooni** for letters/words, **Minjoon** for sentences), served from a public
  Supabase Storage bucket (`ko-sprint`).
- **Scheduler:** FSRS-6 implemented client-side in `app/fsrs.js`.
- **Writing data:** hand-authored normalized `0–100` SVG stroke paths in
  `content/hangul_strokes.json`, shipped with the static app so writing works
  without needing a DB reseed.

All tables are prefixed `ko_sprint_*` and are completely separate from the
JP Atlas production data living in the same project.

## Database (Supabase project `ylceljdbapxeynyqphcr`)

| Table | Purpose |
|-------|---------|
| `ko_sprint_allowed_users` | invite allowlist (email → access) |
| `ko_sprint_learning_items` | 341 content rows (41 hangul + 300 words) as JSONB |
| `ko_sprint_fsrs_cards` | one FSRS card per user × item × direction |
| `ko_sprint_review_logs` | every rating, for streak/accuracy stats |

## Re-running the pipeline (developer)

```bash
# (from this folder; .env holds ELEVENLABS_API_KEY — never commit it)
python scripts/build_content.py        # validate + merge content -> seed + manifest
python scripts/generate_audio.py       # synth MP3s (skips existing)
python scripts/upload_to_storage.py    # push audio + app files to Storage
```
Seeding the DB and storage write access use temporary policies that are dropped
immediately after — see `HANDOFF.md`.

## Updating the app
Edit files in `app/`, copy to `docs/`, commit and push — GitHub Pages redeploys
automatically (~1 min):
```bash
cp app/*.js app/*.css app/*.html docs/ && git add -A && git commit -m "update" && git push
```
